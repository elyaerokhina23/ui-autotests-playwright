# UI-тесты на Playwright и Kotlin

Это моя домашняя работа №5 по курсу автоматизации тестирования. Задача была написать надёжные UI-тесты и разобраться с аннотациями JUnit 5, поэтому я взяла Playwright, написала тесты на Kotlin и запускаю их на [the-internet.herokuapp.com](https://the-internet.herokuapp.com) - небольшом сайте, который специально сделан для тренировки автотестов.

До этого я работала с Selenide для веба и UiAutomator для Android, так что многие идеи здесь оказались знакомыми - просто API другой

## Что внутри

В проекте три файла, и у каждого своя задача:

- **`base/BaseTest.kt`** отвечает за браузер. Он запускает Chromium один раз на тестовый класс и даёт каждому тесту новый чистый контекст браузера, чтобы cookies и авторизация из одного теста не попадали в другой.
- **`tests/login/LoginTests.kt`** проверяет страницу логина: успешный вход, несколько неудачных и выход из аккаунта
- **`tests/pages/PagesTests.kt`** проверяет, что несколько страниц открываются и показывают правильный заголовок

## Что проверяют тесты

На странице логина:
- можно войти с правильными логином и паролем
- при неверном логине, неверном пароле или пустых полях появляется правильное сообщение об ошибке
- после входа кнопка Logout возвращает на страницу логина

Есть ещё тест на восстановление пароля, но пока он отключён - эта часть тестового сайта работает нестабильно

На других страницах тесты открывают `/checkboxes`, `/dropdown` и `/login` и проверяют, что у каждой есть свой заголовок

## Как я использовала JUnit 5

Главное в этой домашке - аннотации, поэтому вот где каждая из них используется и зачем:

- **`@BeforeAll` / `@AfterAll`** - запускают и закрывают браузер один раз на класс, потому что запуск браузера долгий
- **`@BeforeEach` / `@AfterEach`** - открывают чистую страницу перед каждым тестом и закрывают её после
- **`@DisplayName`** - чтобы отчёт читался как список проверок, а не как названия методов
- **`@Tag`** - тесты разбиты на группы `smoke` и `login`, и можно запускать только одну из них
- **`@Disabled`** - для теста восстановления пароля, причина написана прямо в аннотации
- **`@Timeout`** - тест падает, если завис, а не выполняется бесконечно
- **`assertAll()`** - когда тест проверяет несколько вещей сразу, я вижу все упавшие проверки, а не только первую
- **`@ParameterizedTest`** - тест неудачного входа написан один раз и запускается с тремя наборами данных
- **`@Nested`** - тесты "после входа" вынесены в отдельную группу с дополнительным шагом подготовки (логином), чтобы не повторять его в каждом тесте
- **`@TestFactory`** - тесты страниц создаются прямо во время запуска из простого списка страниц и заголовков

## Что я старалась делать правильно

- Искать элементы так, как их видит пользователь - по роли и подписи (`getByRole`, `getByLabel`), а не длинными CSS или XPath селекторами
- Не использовать `Thread.sleep`. Playwright сам ждёт элементы, а его проверки повторяются, пока не пройдут или не выйдет время.
- Делать тесты независимыми, чтобы их можно было запускать в любом порядке

## Запуск тестов

Нужна JDK 21. При первом запуске Playwright сам скачает Chromium, так что это займёт чуть больше времени.

```bash
# все тесты
./gradlew test

# только одна группа
./gradlew test -Ptags=smoke

# один класс
./gradlew test --tests "tests.login.LoginTests"

# один пакет
./gradlew test --tests "tests.pages.*"
```

После запуска отчёт можно открыть в `build/reports/tests/test/index.html`
